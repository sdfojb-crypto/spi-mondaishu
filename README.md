# SPI 問題集

SPI対策の問題集。非言語60問・言語30問（全90問）を一覧から選んで解く静的サイト。学校の Teams チャネルに「Webサイト」タブとして貼って使う想定。

- **ランダム出題**（1問／3問／5問／10問）。分野（すべて／非言語／言語）と難易度（すべて／★1／★2／★3）を選んでから問題数を押すと、その場で出題される
- **連続正解チャレンジ**。選んだ分野・難易度から1問ずつ出題し、正解の得点は早いほど高い（すぐ答えれば1000点、制限時間ちょうどで100点、その間は比例。時間切れ後の正解は100点）。1問でも間違えたらゲームオーバー。自己ベスト（合計得点）は分野×難易度ごとにこの端末に残る
- 全90問の一覧から**好きな問題を選んで解く**こともできる。分野・難易度に加えて状態（未解答／間違えた）でもしぼりこめる
- 解いた問題・正誤・メモはブラウザに保存される
- 非言語（計算問題）には**計算機とメモ**が付く。言語の問題では出ない
- ログイン不要
- 外部のCSS・フォント・スクリプトを一切読まないので、一度開けば回線が不安定でも動く

## 画面

**問題一覧** … 一番上に「出題の条件」（分野・難易度・未解答／間違えた）、その下にランダム出題と連続正解チャレンジのパネル、90問のリスト。解いた問題には○×が付く。

**問題** … 問題文・ヒント・選択肢・解説。タップで解答するとその場で正誤と解説が出る。「前の問題」「次の問題」で順に進める。

**出題の結果** … ランダム出題を最後まで進めると出る。「◯ / ◯ 問正解」と、出題された問題の一覧（○×つき）。行をタップすると、その問題の解説に戻れる。「同じ条件でもう一度」で別の問題が引き直される。

**記録** … 解いた数・正答率・間違えた数と、分野別・難易度別の正答率。

### ランダム出題について

- 「出題の条件」（分野・難易度・未解答／間違えた）は**ランダム出題・チャレンジ・一覧で共用**。「間違えた」を選べば復習の出題になる。チャレンジの自己ベストは条件ごとに別
- 難易度は★の数で表す。★1=基本、★2=標準、★3=やや難。内訳は ★1が22問、★2が51問、★3が17問
- 条件に当てはまる問題数がパネルに出る。それより多い問数を押した場合は、ある分だけ出題される（例：言語かつ★3は5問なので、10問を押しても5問）
- 選ばれる問題は**まだ解いていない問題が優先**される。足りなければ解いた問題からも引く
- 一度解いた問題でも、出題では**解答前の状態から**始まる。何度でも練習できる
- 出題中は「この問題をやり直す」を出さない（結果が確定するまで変えられないようにするため）
- 解かずに「次の問題」で飛ばせる。結果の画面に未解答の数が出る
- 出題中に「やめる」を押すと、その回の結果は出ずに一覧へ戻る。解答そのものは記録に残る

### 図

図が要る問題には図を付けている。全90問のうち13問に、合わせて17枚。

| 置き場所 | いつ出るか | 使っている問題 |
|---|---|---|
| `figure` | 問題文のすぐ下。つねに出る | 表の読み取り（データの表そのもの） |
| `hintFigure` | ヒントを開いたとき | 総当たり戦の空のリーグ表、集合の枠だけのベン図 |
| `answerFigure` | 解答後、解説の下 | ベン図（埋まった状態）、線分図、リーグ表、精算の表 |

図は3種類ある。

- **`table`** … 表。先頭の列は見出し扱い。`{ t: '…', em: true }` と書くとそのセルが強調される
- **`bars`** … 線分図（帯グラフ）。`segs` の `w` は全体に対する割合で、**合計が100になっていないと検証で落ちる**
- **`venn2`** … 2つの集合のベン図。SVGで描く

HTML を文字列で流し込まず、要素を1つずつ作って組み立てている。色はすべてCSSの変数から来るので、ライトでもダークでも読める。

図の指定は `scripts/verify.mjs` が毎回検査する（種類が正しいか、帯の幅の合計が100か、表の列数が見出しと合っているか）。

### ヒント

全90問に1〜2文のヒントが付いている。問題文の下の「ヒントを見る」で開く。

- 解き方の**最初の一手**だけを書いてあり、答えや答えに直結する数値は入れていない
- 問題を移るたびに閉じた状態に戻る。うっかり目に入ることがない
- 検証スクリプトが「ヒントに正解の選択肢がそのまま書かれていないか」を毎回チェックする

### 計算機とメモ

非言語の問題では、問題文の下に「計算機とメモ」の折りたたみが出る。開いた状態は次に開いたときも引き継がれる。

- 電卓は4則演算と符号反転・1文字削除。`eval` は使わず、普通の電卓と同じ「保留中の演算はひとつ」方式で処理している
- 「計算結果をメモへ」を押すと、表示中の数をメモに改行して追記する
- メモは**問題ごと**に保存される。別の問題へ移って戻れば、その問題のメモが出る
- 0で割ると「エラー」と出て、C を押すまで操作を受け付けない

本番で電卓が使えるのはWEBテスティングだけなので、その旨をパネル内に注記してある。

## 使い方（開発側）

Node が必要なのは問題の検証と生成だけ。サイト自体はビルド不要で、そのまま配信できる。

```bash
node scripts/verify.mjs
```

```bash
node scripts/build-data.mjs
```

```bash
node scripts/test-app.mjs
```

`package.json` にまとめてあるので `npm test` / `npm run build` でも動く（依存パッケージはゼロ）。

ローカルで見るときは、`file://` で直接開くとブラウザによっては動かないので簡易サーバーを使う。

```bash
python3 -m http.server 8777
```

## 問題を追加・修正する

編集するのは `scripts/bank/nonverbal.mjs`（非言語）か `scripts/bank/verbal.mjs`（言語）。

各問のフィールド。

| フィールド | 中身 |
|---|---|
| `id` | `nq041` のような一意のID |
| `category` | `非言語` または `言語` |
| `topic` | 推論、損益算、二語関係 など |
| `difficulty` | 1（基本）／2（標準）／3（やや難） |
| `question` | 問題文。改行は `\n` |
| `hint` | 解き方の最初の一手。1〜2文、10〜90字。**答えは書かない** |
| `figure` | 問題と一緒に出す図（任意） |
| `hintFigure` | ヒントの中に出す図（任意） |
| `answerFigure` | 解説の中に出す図（任意） |
| `choices` | 選択肢の配列 |
| `answer` | 正解の**インデックス**（0始まり） |
| `explanation` | 途中式を含む段階的な解説 |
| `timeLimitSec` | 目安時間（20〜300） |
| `reference` | 参考にした分野。**書籍のページや文言は書かない** |
| `check` | 非言語のみ。答えを独立に計算して返す関数 |

### check の書き方

`check(h)` は**正解の選択肢インデックス**を返す。問題を作ったときとは別経路で書くこと。選択肢から逆算すると検証にならない。

```js
check: (h) => h.pick(240 / (1.4 * 0.8 - 1)),
```

`h` に入っているもの。

| 名前 | 用途 |
|---|---|
| `h.pick(v)` | 数値 `v` に一致する選択肢の番号。`"2,000円"` `"5/14"` `"時速24km"` を解釈する |
| `h.pickLabel(s)` | 文字列が完全一致する選択肢の番号 |
| `h.perms(arr)` | 順列を全列挙 |
| `h.combos(arr, k)` | 組み合わせを全列挙 |
| `h.range(n)` | `[0, 1, …, n-1]` |
| `h.labelABC(a, b, c)` | ア・イ・ウ の真偽から「アだけ」「イとウ」などの番号へ |
| `h.CHOICES` | 選択肢の配列 |

列挙で解ける問題は、公式を使わず総当たりで数える。そのほうが検証として強い。

```js
check: (h) => {
  const balls = h.range(8).map((i) => (i < 3 ? 'R' : 'W'));
  const all = h.combos(h.range(8), 2);
  return h.pick(all.filter((c) => c.every((i) => balls[i] === 'W')).length / all.length);
},
```

言語は計算で検証できないので `check` を持たない。かわりに `explanation` に**正解の根拠と、各誤答が外れる理由**を必ず書く。検証スクリプトが解説の長さをチェックする。

### 追加したあと

```bash
node scripts/verify.mjs && node scripts/build-data.mjs
```

### 問題数を変えるときの注意

出題は一覧から選ぶ方式なので、問題を足しても既存の問題の番号や記録はずれない。
ただし**並び順は `data/questions.json` の順**なので、途中に挿入すると以降の「第◯問」がずれる。
番号を安定させたいときは末尾に足すこと。記録と メモは問題IDで保存しているので、番号がずれても失われない。

## 公開する（GitHub Pages）

1. リポジトリを作る。

```bash
git init && git add -A && git commit -m "SPI 問題集"
```

2. GitHub で新しいリポジトリを作る。**Public にすること。** Private リポジトリの Pages は有料プランが必要になる。

3. push する。`<user>` と `<repo>` は自分のものに置き換える。

```bash
git remote add origin https://github.com/<user>/<repo>.git && git branch -M main && git push -u origin main
```

4. GitHub のリポジトリページで **Settings → Pages** を開き、Source を「Deploy from a branch」、Branch を `main` / `(root)` にして Save。

5. 数分待つと `https://<user>.github.io/<repo>/` で開けるようになる。

### 公開してはいけないもの

`.gitignore` で PDF と抽出テキストを除外してある。書籍のファイルをこのフォルダに置かないこと。置く必要がある場合も、コミット前に `git status` で混ざっていないか必ず確認する。

## Teams のタブにする

1. チャネルを開き、上部のタブ並びの右端にある **＋** を押す
2. 一覧から **「Webサイト」**（Website）を選ぶ
3. タブ名（例：SPI 問題集）と、GitHub Pages の URL を入れて保存

### iframe で表示できる理由

Teams の「Webサイト」タブは、指定した URL を iframe で埋め込む。GitHub Pages は `X-Frame-Options` も `Content-Security-Policy: frame-ancestors` も返さないため、そのまま表示できる。

このサイト側でも、埋め込みを妨げるヘッダーやメタタグは一切出していない。自前のサーバーに移す場合は、それらを付けないよう注意する。

### Teams モバイルアプリでの確認項目

スマホから使うのが主な想定なので、公開したら次を確かめる。

- [ ] タブが開く。Teams モバイルは「Webサイト」タブを内蔵ブラウザで開くことがあり、外部ブラウザに飛ばされる場合もある
- [ ] 横スクロールが出ない（画面幅375pxでも崩れないよう作ってある）
- [ ] 選択肢が片手で押せる。タップ領域は最低52px確保してある
- [ ] 端末をダークモードにすると配色が追従する
- [ ] ランダム出題のボタン（1問／3問／5問／10問）が押せて、その場で出題される
- [ ] 残らない場合でも、問題と解説は普通に読める（内蔵ブラウザは localStorage を消すことがある。記録タブにその旨が出る）
- [ ] 一覧をスクロールして90問すべて見える
- [ ] しぼりこみのチップが押せて、件数が変わる

記録が残らない環境でも、問題・解説・アーカイブはすべて動く。保存まわりは全部 `try/catch` で囲ってある。

## 問題の出どころについて

- 出題分野・形式・難易度・解法パターンの把握に、市販のSPI対策書を参考にした。参照元と分析の資料は公開していない
- **問題文・選択肢・解説はすべて新規に作成したオリジナル**で、書籍からの転載はしていない。数値だけを変えた流用もしていない
- 現行SPI3の出題範囲はWebでも裏取りした。書籍と食い違った箇所は手元の資料に記録してある
- 画面下部に「参考に作成したオリジナルです。検証していますが誤りがある場合があります」と常時表示している

### 実機確認で見つけて直した不具合

画面の出し分けに `hidden` 属性を使っているが、`.view` と `.result` に `display: flex` を指定していたため、ブラウザ既定の `[hidden] { display: none }` を上書きしてしまっていた。タブを切り替えても前の画面が消えず、未解答の段階で「解説」の見出しが見えていた。

`[hidden] { display: none !important; }` を追加して解消した。DOM上の `hidden` プロパティは正しく切り替わっていたため、Node のテストでは検出できなかった。同じ不具合が戻らないよう、`test-app.mjs` に CSS を直接見る回帰チェックを追加してある。

### アセットのキャッシュについて

`index.html` から読む CSS と JS には `?v=2` のようなバージョンを付けてある。**中身を更新したらこの番号を上げること。** 上げないと、すでに開いたことのある人のブラウザが古いファイルを使い続ける。実際、上の不具合を直したときも番号を上げるまで修正が反映されなかった。
